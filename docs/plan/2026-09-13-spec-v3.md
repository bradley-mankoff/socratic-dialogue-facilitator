# Socratic Dialogue Facilitator v1 — Spec (v3 consensus)

Source: wayfinder map (7/7 resolved), SDF-N1 v1, grok-4.6 xhigh v1 review (needs-rework), v2 revision, grok v2 review (needs-rework, 4 blockers), live debate round 2026-09-13 (14 agreements + 3 contested, all 3 conceded to reviewer). This v3 is the consensus text both parties approved as codable. Fixture X: Justice (Republic Book I). Terms: Target (X), Board, Active definition, Counterexample shapes 3a/3b, Iteration chain, Canvas, Handle, Census, Q.

## Problem Statement

People holding a Socratic dialogue today lack what the ancients had: working memory for the whole argument and a shared board. Across a live session or a multi-day async exchange, a modern room loses track of the north-star question, the answerer's initial response, each rebuttal, which counterexamples hit which definition, and the current best attempt. Browser tabs, docs, and chat threads record words but track no definition state, so iterations stall or silently restart. Source outage must read as outage, never as consensus.

## Solution

A self-hosted (host Mac on-only), free-or-metered-by-choice, multi-party Socratic dialogue facilitator. One board per Target X toggles freely between async (persistent, days-long) and live (voice-transcribed) discussion. A facilitator keeps the board: auto-pulls cited canonical definitions, tracks one active definition under elenchus, records labeled 3a/3b counterexamples with majority-vote verdicts, and chains revisions. Two modes set its voice: LLM Participates (full peer, optionally holding the Socrates questioner seat) or LLM Facilitates (scorekeeper only). Every dialogue closes with an interactive 2-D canvas summary, exportable as PNG.

## Verdict predicates (closed; sole source of truth — the map is historical)

- Handle: unique board-local identity string. Voiceprint enrollment, stable provisional labels, and async names all bind to handles; duplicate display names suffix mechanically (Alex, Alex-2) via atomic registry. Honor-system names ARE the set. The facilitator is a handle only in Participates mode, never a second franchise for a Socrates-holding human.
- BoardCensus(t): handles existing at t.
- Every majority question is a Q: counterexamples, mode switches, Socrates swaps, active-claim switches, ingress selection, tiebreak invocations, board close. Census(Q) = BoardCensus(Q.openedAt) ∪ {handles that subsequently cast on Q}. Late non-voters never enter Census(Q) and stall only that Q.
- Standing (CE-level view): stands-ballots > rebutted-ballots. 0–0 is not standing.
- Refuted (node-level): some attached CE is standing AND 2 * stands > |Census(CE)| (strict majority; halves, ties, shortfalls fail).
- Counted ballot per (handle, CE): latest EXPLICIT ballot if any exists, else latest ambient; classifier retraction and self-correction mutate ambient only and can never demote an explicit ballot. Server receive time orders. One ballot per natural person — ambient and explicit deduped by speaker.
- Tie ⇒ not-refuted, with exactly one exception: rooms whose human count is 1, where the human ballot is decisive.
- Re-vote is not a new Q: further casts on the same Q; latest counted ballot rules; re-votes may un-refute the ACTIVE node only (inactive nodes are frozen history).
- Medium toggle (async ↔ live): no census mutation, no re-tally of settled Q.
- Mode switch on OPEN Q only: Participates→Facilitates withdraws the facilitator ballot and drops it from Census(Q), then recomputes; Facilitates→Participates adds it (ballot only when cast). Settled Q untouched.
- Facilitates tiebreak: any tie may be resolved by invoking the facilitator, but invocation is itself a governance Q (majority, at most one successful invoke per CE, system-logged). On pass the facilitator casts exactly one labeled, reasoned tiebreak ballot. Still not refuted ⇒ stays not-refuted, no second invoke.
- Close is an ordinary governance Q (majority; the facilitator never proposes it). On pass: all open tallies freeze, the tray snapshots as carried_unresolved into the graph JSON, in-flight ambient hypotheses are discarded untallied, the canvas finalizes. Closed is terminal; follow-ups are new labeled boards.

## User Stories

Board and modes:

1. As a host, I want to open a board for one Target X with a distinct label — identity is (X, label) — so that parallel rooms for one X are possible and the room shares a single north star.
2. As a host, I want a new X to mean a new board, so that arguments never cross-contaminate.
3. As a participant, I want to choose LLM Participates or LLM Facilitates per board, so that the room controls the facilitator's voice.
4. As a participant, I want the mode changeable later by majority with the switch logged as a system event, so that a stuck room can always open the hatch.
5. As a participant, I want to toggle the same board between async and live freely, so that busy schedules and live sessions share one argument.
6. As a participant, I want everything except the closed live-ephemeral set (mic/VAD state, transcript cursor, partial hypotheses, search spinners, live socket handles, raw audio buffer) to survive a toggle — in-flight tallies explicitly persist and stay visible — so that nothing decided is ever lost changing mediums.
7. As a late joiner, I want the pinned initial response, version history, settled votes, AND open tallies replayed, casting immediately on any open Q, so that I enter with full franchise and nothing vote-shaped stays hidden.

Definitions:

8. As a participant, I want canonical definitions auto-pulled when a board opens from Wiktionary-first plus Free Dictionary API second vote only, so that the room starts from highly-cited ground with zero keys and zero meters running.
9. As a participant, I want every canonical to carry source, link, access date, and license, so that authority is checkable.
10. As a participant, I want canonicals immutable and cached per X (shared across same-X boards), so that re-pulls never rewrite mid-fight history.
11. As a participant, I want to claim a canonical as my own (copied, source-tagged) or author an original, so that who holds what is traceable.
12. As a participant, I want exactly one active definition front-center with counterexamples nearby (nearness is layout, not data), so that attention is never split.
13. As a defender, I want revisions to create new version nodes rather than edits, with attached counterexamples copied into a visible tray as carried_unvoted (pressed → attaches unvoted to the active node as a new Q; discarded → system-logged; tray affects neither verdicts nor the canvas live path), so that the road stays inspectable and old strikes are explicitly re-pressed or dropped.
14. As a participant, I want to pan history toward the past over the same graph store the canvas reads (one store, two views), so that superseded attempts and their frozen tallies stay reachable.

Counterexamples and votes:

15. As a challenger, I want counterexamples labeled 3a (IS-X-but-fails) or 3b (fits-but-is-NOT-X) against the active definition, so that the strike's shape is explicit.
16. As a participant, I want each counterexample's stands/rebutted status to change only by tally under the closed predicates, so that no one flips history unilaterally.
17. As a participant, I want refutation decided by the integer predicate (strict census majority; ties fail; the single 1-human exception; tiebreak-invoke rule), so that verdicts are democratic, legible, and computable.
18. As a participant, I want votes tallied ambiently from informal speech/text plus explicit calls, deduped to one counted ballot per person with explicit-over-ambient precedence, so that voting never breaks flow and never double-counts.
19. As a participant, I want mistallied ambient votes to self-correct (ambient-layer only, never demoting explicits) without derailing, so that false positives cost nothing.
20. As a participant, I want the who-voted-what scoreboard current in both modes (facilitator row appears only for Participates ballots and invoked tiebreaks), so that the count lives somewhere trustworthy.
21. As a defender who lost a vote, I want advancement by persuasion (re-vote) or mode-switch rather than override, so that verdicts mean something yet nobody is ever stuck.

Socrates seat and facilitator voice:

22. As a room, I want a Socrates questioner seat that is never vacant — held by a human (first holder set at creation, then rotation and tag-outs as named-swap majority Qs) or by the facilitator in Participates mode — so that questioning always has an owner.
23. As a learner in a Socrates-led room, I want teaching callouts labeled META, capped at one per defender turn live and one per revision node async (extras mechanically dropped as moot), distinct from ELENCHUS challenges, so that lessons never masquerade as strikes. Facilitates rooms have zero META.
24. As a participant, I want every facilitator contribution labeled with its type AND quoted target id it responds to, over WebSocket/poll only, so that a lagging facilitator is never mistaken for commenting on the latest words.
25. As a participant, I want the facilitator to drop a point gone moot mid-composition, so that stale interjections never land.
26. As a participant, I want facilitator ballots (Participates votes and invoked tiebreaks) posted with visible reasons at equal weight, so that its reasoning is auditable.
27. As a participant in Facilitates mode, I want zero unprompted voice (no votes except an invoked tiebreak, no suggestions, no callouts, no META), so that the room owns the argument entirely.

Live voice:

28. As a live participant, I want confirmed transcript segments visible within 3s after voice-activity end — no word-streaming display (deliberately out: distracting) — so that speech becomes record without visual noise.
29. As a live participant, I want live speaker labels from enrollment-cosine matching (published threshold tuned on fixture, exclusive assignment, below-threshold and overlaps kept provisional), backfilled later by the post-hoc diarization pass over HostMic audio, so that attribution starts immediately and converges.
30. As a live participant, I want a ~30s calibration enrollment at session start binding my voice to my handle, so that I am never Person 1.
31. As a guest who skips enrollment, I want a stable provisional label with full franchise equality, so that I can still be counted.
32. As a room, we meet live under exactly one ingress per session (switching ingress is governance Q): HostMic (one room capture; stories 29–31 apply) XOR GuestTabs (each remote tab captures mic over the board WebSocket as Opus; identity = handle bound to socket; mixer concatenates already-segmented utterances; no cosine needed). A parallel phone call is not an ingress — on HostMic it is a documented footgun that will be transcribed. No call-platform bots, no simultaneous hybrid.
33. As a builder, I want it on record that call-platform joining and simultaneous-hybrid ingress are intentionally out, so that tickets never re-litigate live topology.

Search and canonicals:

34. As a participant, I want the canonical pull to converge multiple dictionaries with dedup that NEVER merges distinct senses on wording overlap (case/whitespace normalization only; near-duplicate rivals accepted as the cost), so that Justice-as-virtue and Justice-as-institution stay rivals.
35. As a participant, I want source failure to degrade gracefully — surviving sources first, and an explicit empty state when all sources are down or X has no dictionary hit — so that outage reads as outage, never as consensus.
36. As a participant, I want web counterexample search strictly on demand, so that metered calls never fire by themselves.
37. As a participant, I want SEP reachable only as an explicitly requested, clearly labeled voice via link-out or pasted excerpt (no crawler), so that deep entries are available without privileging philosophers by default.
38. As a participant, I want philosopher lookups never unprompted, so that the canon never steers silently.

Canvas and hosting:

39. As a participant, I want the closing canvas to show every attempted definition as nodes and refutations as labeled edges with the active chain highlighted (tray items render as carried_unresolved off the live path), so that the whole dialogue reads at a glance.
40. As a participant, I want to pan/zoom the canvas and export PNG only, so that the result travels beyond the app.
41. As a host, I want the board's identity to be durable local state (X, label — not the share URL): persist every mutation to disk, resume after sleep/crash with live mics dropped and centroids kept, guests rejoining on whatever the current URL is. Share URLs come from one Quick Tunnel command (rotating, dev-SLA) or QR LAN fallback — no stable-public-URL promise without a named tunnel.
42. As a host on same-WiFi fallback, I want a QR-joinable local URL with zero third parties, so that the room works fully offline-ish.
43. As a participant, I want mode/role/close/invoke events auto-posted as system log entries (never facilitator contributions), so that governance leaves a trail the voice rules cannot touch.

Operations and edge cases:

44. As a host, I want a metered-use notice before opening a board on the hosted-API brain path — including that ambient tally costs about one model call per confirmed segment — with a documented local-model path to zero, so that cost is consented, never ambient.
45. As a host, I want model downloads (transcription, diarization, enrollment, local brain) to progress visibly and fail with a named missing piece, including HF accept/token where gating, without ever blocking the dictionary path, so that first run is debuggable.
46. As a host, I want to open a second board for the same X with a distinct label (shared canonical cache keyed by X), so that parallel rooms are possible.
47. As a room, we close a dialogue by ordinary majority Q, whereupon tallies freeze and the canvas finalizes; closed is terminal and the facilitator never proposes it, so that endings are owned.
48. As a room on a public URL, we run on honor system with enrollment display names as identity, so that v1 ships without auth while saying so openly.
49. As a participant, I want overlapping speech labeled provisional with no identity guess, so that crosstalk never misattributes.
50. As a builder, I want a named Mac acceptance script (enroll, run Republic-I slice, bind labels, resolve test votes, export PNG; voice topology fixed to HostMic until call paths exist) distinct from the repo gate, so that hardware-gated behavior is verified without pretending pytest covers it.
51. As a participant, I want English-only declared for v1, so that model and dictionary coverage are honest constraints.
52. As a host, I want to export the raw recording before auto-delete-after-post-hoc-pass, so that the default stays private without losing anything deliberately kept.

## Implementation Decisions

- Research verdicts adopted: faster-whisper local CPU int8 segment-final loop (≤3s post-VAD-end target) with Silero VAD gating, larger async pass; enrollment centroids (wespeaker-voxceleb-resnet34-LM, ~30s calibration, cosine match, exclusive assignment, fixture-tuned threshold, SPEAKER_XX fallback) plus pyannote speaker-diarization-community-1 post-hoc relabel over HostMic; Wiktionary-first chain (Free Dictionary API second, 522-tolerant; agreement-as-proxy; normalization and non-merge per story 34; cite-every-def); Cytoscape.js canvas (PNG-only; graph JSON including carried_unresolved is the asserted artifact; assertions cover near-duplicate rivals so tickets never revive Jaccard); Quick Tunnel default URL with no-SSE constraint (single board WebSocket carrying board events, Opus guest audio, and WS/poll fallbacks); durable local board state with per-mutation persistence.
- Facilitator brain: hosted API default (concrete provider/model at implementation; grok-class preferred given room tooling); local-model path must pass the transcript→vote fixture set to qualify as the free Facilitates configuration; transcript/timing fixtures (including explicit-beats-ambient and late-ambient cases) are the stub seam for ambient tally in gate and in local qualification alike.
- Predicates section above governs; map tickets 02/03 are history, not law. SEP link-out/paste only; fixture Republic quotes are user-owned attempts, never auto-canonicals.
- Built-in host mic assumed working; no independent mic testing.
- Seams: headless board-state machine asserting the closed predicates (primary); stubbed-HTTP dictionary chain incl. all-down empty state; graph-JSON assertions plus Mac-only golden PNG; transcript/timing fixtures for ambient tally.
- Stack and module decomposition deferred to to-tickets/implementation; no file paths fixed by this spec.

## Testing Decisions

- External behavior only; repo gate runs the suite green before any review.
- Board-state machine: census freeze, integer refute, tie rule plus 1-human exception, mode-switch recompute, unilateral-invoke rejected (invoke is governance Q), carry-tray, inactive freeze, un-refute-active-only, majority governance incl. close, system-log separation — all headless.
- Dictionary chain: convergence, single-source survival, all-down empty state, sense non-merge on Justice, near-duplicate acceptance row.
- Canvas: graph-JSON assertions (nodes, labeled edges, active chain, carried_unresolved) in gate; golden PNG Mac-only.
- Ambient tally: transcript/timing fixtures incl. explicit-beats-late-ambient and dedup-by-speaker.
- Hardware-gated layers: Mac acceptance script only.
- Greenfield; pytest -q is the gate.

## Out of Scope

- Non-definitional claims — future direction.
- Plato-corpus rebuild or philosopher-privileging defaults (fixture quotes are user attempts, never auto-canonicals).
- Always-on cloud, multi-tenant auth, paid tunnels as default, stable public URL without named tunnel.
- Pan/zoom renderer from scratch; SVG export.
- Async digests and nudges; word-streaming transcript display.
- Any metered call without deliberate trigger (mode/API choice is the trigger); per-guest mic plumbing beyond GuestTabs; call-platform bots; simultaneous-hybrid ingress.
- Recording retention beyond auto-delete-after-post-hoc-pass unless the host exports first (story 52).
